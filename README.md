# APB_I2C_MULTI
VHDL code for a APB to I2C IP with a configurable number of I2C interfaces

The VHDL code provides a I2C interface which can connect to the APB bus. It is currently used with Lattice. 
Once it is integrated the following commands are available. We might add C code here later. 

This document shows the VHDL parameters first to configure the IP, then it shows the registers to run the IP.

## VHDL Parameters

There are three VHDL parameters (generic) which can be configured. 
- num_i2c
- input_clk
- bus_clk

The three parameters are used to define the speed of the interface and the number of I2C channels. 
In the moment there is no means to set the speed dynamically during operation but needs to be set up front. 
Probably a simple change later on. 

### input_clk
The input_clk is the clock speed of the system. This is the clock speed which is seen at the PCLK.

### bus_clk
This is the desired clock speed of the I2C interface. This is basically the speed of SCL.

### num_i2c
This is the number of I2C interfaces which are generated by the generate statement. 
This number is between 1 and 32. We can not generate more than 32 interfaces at this point. 


## Control Registers for the I2C
Usually the interface can be mapped to a base address say in a lattice environment. This is done elsewhere. 
Once the base address is established relative addresses from that base address allow to control the interface. 
The address space of this interface is 12-bits which means it occupies 4096 bytes of address space. 
All parameters are mapped to 4-byte integers. Therefore the addressing is always multiple of 4 or word alligned. 
Therefore the lower two bits of the addresses always need to be zero as shown in the following explanation. 

### Main concept
When we generate a number of I2C interfaces the addresses space is calculated accordingly. Each I2C interface 
occupies a section of 128 bytes. The device always occupies 4096 bytes which means that the maximum number of I2C interfaces we 
can define is 32. Besides the addresses which are specific to the individual I2C interface there are some control words which occupy just one 
32-bit word whereas each bit represents one I2C interface. 
We therefore have general control registers and individual (i.e. per I2C) control registers.

### General or BITWISE Registers

- ENABLE
- RW
- BUSY
- NEXT_WRITE
- NEXT_READ
- ACK_ERROR

These are 32-bit registers whereas each bit represents one I2C interface. 

### Individual Registers

- ADDRESS
- REGISTER
- DATA
- NUM
- DATA_READ[0]
- DATA_READ[1]
- DATA_READ[2]
- DATA_READ[3]
- DATA_READ[4]
- DATA_READ[5]
- DATA_READ[6]
- DATA_READ[7]

We allow block read for upto 8 bytes at a time. The number of registers is provided by NUM for read. Write has two modes.
One mode is to write only the ADDRESS and REGISTER, which is a precursor for a read cycle. In this case the NUM needs to be set to 0. 
If we write ADDRESS, REGISTER and DATA then the NUM needs to be set to 1. For write we support only NUM = {0,1} and for read we support only 
NUM = {1,2,3,4,5,6,7,8}.
